# Навігатор студента – Lesson 02: Document API (OpenRouter)

Почніть із головної точки входу курсу – [INSTRUCTION.md](../INSTRUCTION.md). В ній описано повний цикл роботи. [STUDENTS.md](../STUDENTS.md) містить точні Промпти 1 і 2, правила для гілки, папки `my-dev/` та здачі. Ця сторінка пояснює маршрут саме для Lesson 02 OpenRouter.

## Порядок роботи

1. **Підготуйте заняття за `INSTRUCTION.md` і `STUDENTS.md`.** В Промпті 1 виберіть Lesson `02` і трек `OpenRouter`. Після його виконання працюйте в гілці `lesson-02-llm-api-openrouter`, в папці `my-dev/lesson-02-llm-api-openrouter/`. Агент створює її зі `starter/`; вручну файли не копіюйте. Не змінюйте `starter/`, `solution/` або `dev/`.

2. **Прочитайте [homework.md](./homework.md).** Він визначає обов'язкові вимоги, додаткові поглиблення та критерії здачі. Якщо приклад в будь-якому гайді відрізняється від вимог homework, для приймання керуйтеся homework.

3. **Виконуйте [roadmap-code-guide.md](./roadmap-code-guide.md)** в `my-dev/lesson-02-llm-api-openrouter/`, послідовно від кроку 1. Він задає повний маршрут реалізації; мінімум для здачі визначає homework. Не потрібно наперед читати всі довідки. [starter-code-guide.md](./starter-code-guide.md) відкривайте, коли потрібне пояснення структури стартового коду. [dev-migration-guide.md](./dev-migration-guide.md) пояснює концептуальний перехід від CLI до HTTP API та початкові перевірки.

   Після роботи за roadmap заповніть `my-dev/lesson-02-llm-api-openrouter/final-project-ideas.md` за контрольною точкою з [homework.md](./homework.md): запропонуйте 2–3 теми, для кожної вкажіть проблему, цільового користувача, очікуваний результат агента, джерела даних і ризики.

4. **Після реалізації перевірте роботу з кореня репозиторію:**

   ```bash
   yarn check:my:lesson02:openrouter
   yarn eval:my:lesson02:openrouter
   ```

   Для цих offline-перевірок не потрібні `.env` та API key. На початковому starter `check:my` навмисно зупиняється через 12 `it.todo`; це не збій середовища. Запустіть його знову після реалізації тестів. Offline eval має дати 5/5, але сам по собі не доводить доступність live-провайдера.

5. **Здайте роботу через Промпт 2 зі [STUDENTS.md](../STUDENTS.md).** Запускайте його після перевірок і звірки з homework. Він готує перевірене посилання на гілку та папку `my-dev/` в вашому fork для LMS. Не створюйте MR/PR до головного репозиторію курсу для звичайної здачі.

## Необов'язковий запуск сервера

Для ручної HTTP-перевірки запустіть `yarn env:init` в корені, локально додайте `OPENROUTER_API_KEY` до кореневого `.env`, а потім виконайте:

```bash
yarn dev:my:lesson02:openrouter
```

Ключ не надсилайте в чат і не додавайте до Git. `/health` не викликає модель; extraction та summary запити можуть звертатися до провайдера і витрачати баланс. Live-перевірка не є умовою здачі.
