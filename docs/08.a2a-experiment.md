> **Контекст.** Базова практика Lesson 08 залишається самодостатньою. Це додатковий експеримент, а не нова обов’язкова вимога домашнього завдання. `ReportWorkflow` залишається супервізором на TypeScript; лише виклики дослідника проходять через A2A.
>
> **Основа цього варіанта:** фактичні файли `solution/src/services/report-workflow.ts` і `solution/src/services/openrouter-report-workers.ts` із наданої практики `lesson-08-multi-agent-workflow-openrouter`. Нижче використано їхні справжні контракти, а не приблизні аналоги.

У комплекті вже є каталог `a2a-lab/` з кодом, конфігурацією та тестами. Основну практику не потрібно переписувати. Додаток А містить повний текст нових файлів, однаковий із файлами в архіві.

## Швидкий запуск

Потрібні Node.js **22.16.0 або новіший** та доступ до npm для встановлення пакетів. Команди виконуються в розпакованому каталозі практики:

```bash
cd lesson-08-multi-agent-workflow-openrouter/a2a-lab
npm install
npm test
```

Після встановлення залежностей тести не звертаються до провайдера моделей. Вони запускають локальний HTTP-сервер і перевіряють справжній A2A-обмін із тестовими виконавцями.

У першому терміналі, з каталогу `a2a-lab/`:

```bash
npm run start:research
```

У другому терміналі, з того самого каталогу:

```bash
npm run start:report
```

У третьому терміналі PowerShell:

```powershell
$body = @{ message = 'AI-агенти в розробці ПЗ' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:3000/api/workflow/report' -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) | ConvertTo-Json -Depth 20
```

Альтернатива для Bash:

```bash
curl --fail-with-body http://127.0.0.1:3000/api/workflow/report \
  -H 'Content-Type: application/json' \
  -d '{"message":"AI-агенти в розробці ПЗ"}'
```

**Початковий режим — `mock`.** A2A-клієнт, HTTP, картка агента, серіалізація і супервізор працюють реально, але всі звернення до моделей замінені тестовими виконавцями. Ключ не потрібний, витрат на LLM немає. Звіт явно містить позначку «ДЕМОНСТРАЦІЙНИЙ», а джерела мають тестові адреси `example.invalid`. Це не результати вебпошуку.

Результат містить `status: "approved"`, текст, джерела, метрики та додаткове поле HTTP-обгортки:

```json
{
  "lab": {
    "backend": "mock",
    "realModelCalls": 0
  }
}
```

Це лише фрагмент відповіді; повний результат повертає справжній `ReportWorkflow`.

## 1. Концепція та мотивація

У базовій практиці `ReportWorkflow` викликає методи локальних об’єктів `ResearchWorker`, `WriterWorker` і `ReviewerWorker`. Усередині live-виконавців уже є мережеві звернення до OpenRouter. Отже, «локальний Worker» означає локальну межу між workflow та об’єктом, а не повну відсутність мережі в роботі виконавця.

В експерименті локальний ResearchWorker замінено адаптером `A2AResearchWorker`. Для супервізора це той самий метод `research(topic, focus, signal)`. Адаптер перетворює його аргументи на A2A-повідомлення й передає окремому сервісу. Сервіс викликає існуючого дослідника, повертає результат, а адаптер перевіряє його перед передаванням у workflow.

**Змінюється спосіб взаємодії, а не порядок кроків.** A2A не вимагає LLM-супервізора, динамічного планувальника або ієрархії «старший агент — підагенти». Незалежний сервіс також не стає більш автономним у виборі дій лише через перенесення в інший процес.

## 2. Поточна архітектура та справжні контракти Lesson 08

```text
POST /api/workflow/report { message }
                  │
                  ▼
          ReportWorkflow — TypeScript
                  │
       ┌──────────┴───────────┐
       ▼                      ▼
Researcher(opportunities)  Researcher(risks)
       └──────────┬───────────┘
                  ▼
       validate + deduplicate
                  ▼
                Writer
                  ▼
               Reviewer
        ┌─────────┴───────────┐
     approved               revise
        │                     │
   результат            до 2 доопрацювань
                              │
               третій revise → limit_reached
```

`ResearchBrief` у наданому коді містить `focus`, `summary`, `sources` та `tokenUsage`. Усередині `tokenUsage` використовуються **`inputTokens`, `outputTokens`, `totalTokens`**. Поля `promptTokens` і `completionTokens` не відповідають цьому контракту.

Автор і рецензент працюють з тими самими зведеннями та списком джерел. `reviewFeedback` передається автору під час повторного написання; початкова чернетка не рахується доопрацюванням. Максимум — три виклики Writer і три перевірки Reviewer. Після двох доопрацювань Reviewer ще може схвалити чернетку; `limit_reached` повертається, якщо він знову вимагає `revise`.

У нормальному завершеному маршруті з Reviewer метрика `modelCallCount` дорівнює 4, 6 або 8. Це лічильник логічних викликів ролей у цьому workflow, **не незалежний облік HTTP-спроб провайдера**. У mock-режимі він теж може дорівнювати 4, хоча реальних LLM-викликів нуль. Окреме поле `lab.realModelCalls: 0` усуває цю неоднозначність. У live-режимі це поле має `null`: точну кількість фактичних спроб ця додаткова HTTP-обгортка не вимірює.

Схема валідації та коректні індекси цитат перевіряють структуру й зв’язування джерел, але не гарантують правдивість тверджень. Схвалення Reviewer також не є математичним доказом фактів.

## 3. Цільова архітектура з A2A

```text
Процес 1: report-app, 127.0.0.1:3000
  HTTP → ReportWorkflow
           ├─ A2AResearchWorker ──────────────┐
           ├─ локальний Writer              │
           └─ локальний Reviewer            │
                                             │ A2A 1.0 / JSON-RPC 2.0 / HTTP
                                             ▼
Процес 2: research-agent, 127.0.0.1:4100
  AgentCard + офіційний JSON-RPC adapter SDK
       → DefaultRequestHandler
       → ResearchAgentExecutor
       → ResearchWorker
            mock: тестове зведення
            live: оригінальний OpenRouterResearchWorker
                    → Responses API + openrouter:web_search
       → Message з JSON payload
```

Обидва фокуси обслуговує один research-agent двома незалежними викликами. Не потрібно запускати два сервери дослідника або створювати окрему модель для кожної ролі.

У live-режимі використовується саме оригінальний OpenRouter-адаптер. У ньому зберігаються `tool_choice: "required"`, `max_tool_calls: 1`, налаштування пошуку, перевірка завершеності відповіді, обробка цитат, нормалізація токенів і передавання `AbortSignal`. Окремий спрощений `extractSources()` для лабораторної не створюється.

Усі URL OpenRouter та API-ключ залишаються в налаштуваннях відповідного процесу. В A2A-запит не передаються ключі, системні промпти або вся історія інших ролей.

## 4. AgentCard і формат протоколу

Для цього сервісу обрано стандартний well-known шлях:

```http
GET http://127.0.0.1:4100/.well-known/agent-card.json
```

A2A описує також інші способи отримання картки; не кожен сумісний deployment зобов’язаний робити її загальнодоступною саме так. У цій lab картка відкрита тільки на loopback-інтерфейсі.

Картка оголошує `supportedInterfaces` з `protocolBinding: "JSONRPC"`, `protocolVersion: "1.0"` та адресою `/a2a`. Вона створюється через **`AgentCard.fromJSON()`**, що заповнює необхідні стандартні поля внутрішньої protobuf-моделі SDK. Це усуває проблему неповного plain object, помилково оголошеного як повний `AgentCard`.

Картка повідомляє, що сервіс уміє робити, але не надає права доступу. Лабораторний клієнт додатково перевіряє адресу: тільки налаштований `http://127.0.0.1:<port>`, потрібний `/a2a`, без перенаправлень на інший origin. Це локальне правило безпеки нашого застосунку, не універсальне обмеження A2A.

### Два представлення одного повідомлення

Мережева ProtoJSON-форма містить `role: "ROLE_USER"` та частину `data`. У TypeScript-моделі SDK роль є enum, а дані частини читаються через `part.content.$case` і `part.content.value`.

Запит створюється через `SendMessageRequest.fromJSON()`, відповідь — через `Message.fromJSON()`. Клієнтський `sendMessage()` повертає **`Message | Task` без зовнішнього `{ message: ... }`**. Сама JSON-RPC-обгортка залишається справою SDK, а не `parseResearchBrief()`.

### Контракт нашого JSON payload

На вхід досліднику передається:

```json
{
  "schemaVersion": 1,
  "topic": "AI-агенти в розробці ПЗ",
  "focus": "opportunities"
}
```

У відповіді `data` містить `schemaVersion`, `backend` і `brief`. `brief` відповідає справжньому контракту практики. `schemaVersion: 1` — **версія нашого payload**, не заміна `protocolVersion: "1.0"` у картці.

Режим `backend` перевіряється клієнтом: live-застосунок не прийме mock-зведення як результат реального пошуку. Так само повернений `focus` перевіряється, а не примусово переписується очікуваним значенням.

## 5. Клієнтський A2AResearchWorker

Адаптер реалізує існуючий `ResearchWorker`. Він перевіряє тему і фокус, створює deadline, отримує картку, обирає дозволений інтерфейс, надсилає повідомлення й перевіряє повернене зведення. Повний код наведено в додатку А.

Один ліміт часу охоплює **discovery та SendMessage**, а не лише другий мережевий запит. Зовнішній сигнал клієнта комбінується з локальним timeout. Коли сигнал уже скасований, жодне мережеве звернення не починається.

Парсер очікує повідомлення від `ROLE_AGENT` з одним `application/json` data part. Він не намагається вгадати JSON у довільному тексті й не підставляє нульові токени замість відсутніх обов’язкових полів. Zod перевіряє назви полів, типи, непорожні джерела, допустимі HTTP(S)-адреси та невід’ємні цілі лічильники.

Успішний сценарій тут — **Message → Message**. `Task` не перетворюється на успіх і не розбирається як зведення. Зокрема, SDK може оформити помилку виконання як failed Task; клієнт відхиляє такий результат, і workflow не запускає Writer з неповними даними. Polling та читання Artifact не реалізовані й не потрібні для обраного сценарію.

## 6. Research Agent, виконання і скасування

### 6.1. Серверна послідовність

`research-app.ts` підключає офіційні `agentCardHandler` і `jsonRpcHandler`. `DefaultRequestHandler` створює контекст, а `ResearchAgentExecutor` перевіряє вхід перед викликом доменного дослідника. Відповідь публікується через `AgentEvent.message()`.

Executor використовує `context.contextId`, а не вигадує незалежний контекст для відповіді. Він не вважає саму наявність `userMessage.taskId` доказом запиту на продовження: SDK може призначати цей ідентифікатор під час підготовки контексту. Для заборони продовження існуючої задачі перевіряється `context.task`.

Це не повторна реалізація бізнес-логіки Researcher. Executor викликає той самий метод `research(topic, focus, signal)`, який уже є в практиці, і перевіряє результат перед публікацією.

### 6.2. Межі помилок

Некоректні `topic`, `focus`, `schemaVersion` та форма повідомлення відхиляються до звернення до провайдера. Внутрішня помилка Researcher не передається клієнту разом із сирим provider error body.

HTTP-обгортка report-app повертає `400 INVALID_INPUT` для некоректного `message` і `502 REPORT_WORKFLOW_ERROR` для невдалого виконання workflow. Точний текст системного exception не є контрактом. Тіло відповіді містить підготовлену помилку, а не довільні подробиці зовнішнього сервісу.

`approved` і `limit_reached` повертаються з HTTP 200. Другий статус означає, що контрольований цикл завершився без схвалення останньої чернетки, а не що сталася транспортна помилка.

### 6.3. AbortSignal не є віддаленою командою CancelTask

Сигнал у `client.sendMessage(..., { signal })` припиняє клієнтське очікування й керує локальним запитом. Він не серіалізується в JavaScript-об’єкт на іншому сервері й не гарантує припинення вже розпочатої роботи Researcher.

На research-agent діє **власний серверний deadline**. Він передається оригінальному OpenRouterResearchWorker, який підтримує `AbortSignal`. Типові межі: OpenRouter-клієнт — 40 секунд, серверний дослідник — 45 секунд, discovery разом із A2A-запитом — 60 секунд. У report-app загальний deadline — 240 секунд. Значення можна налаштувати в `.env`.

`CancelTask` — окрема протокольна операція для задач із життєвим циклом. У цій lab Executor явно повертає unsupported для такого механізму. Віддалене скасування не оголошується «непотрібним»: це свідомо не реалізована можливість мінімального експерименту, частково компенсована серверним timeout.

`Promise.all` також самостійно не скасовує іншу дослідницьку гілку після першої помилки. Workflow не переходить до Writer, але вже розпочата віддалена операція може виконуватися до завершення або власного deadline.

### 6.4. Безпека локального запуску

Обидва сервери прив’язані до **127.0.0.1**, а не до всіх мережевих інтерфейсів. `UserBuilder.noAuthentication` обрано тільки для локальної лабораторної. Не публікуйте ці порти через тунель і не використовуйте анонімну конфігурацію як production-рішення. Будь-який довірений локальний клієнт, що має доступ до порту, потенційно може ініціювати live-запит.

Ключ зберігається в `.env`, який виключено з Git. У mock-режимі клієнт OpenRouter не створюється. Назви моделей не беруться з довільного A2A payload: їх задає власник процесу через конфігурацію.

## 7. Що змінилося при винесенні Worker

| Критерій                | Базова практика                     | A2A-експеримент                                                    |
| ----------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| Межа виклику дослідника | Локальний метод об’єкта             | Серіалізоване повідомлення через HTTP                              |
| Керування маршрутом     | `ReportWorkflow`                    | Той самий `ReportWorkflow`                                         |
| Процеси                 | Один для координації ролей          | Окремі report-app і research-agent                                 |
| Дані на межі            | `ResearchBrief`                     | A2A Message з перевіреним payload і `ResearchBrief`                |
| Помилки                 | Обробка виклику у спільному процесі | Додатково недоступність сервісу, timeout, protocol/schema mismatch |
| Ізоляція ресурсів       | Спільні пам’ять і процес            | Власні процеси; падіння сервісу не зобов’язує зупиняти report-app  |
| Доступ до моделей       | Усередині локальних ролей           | Researcher у сервісі; Writer і Reviewer у report-app               |

Це порівняння **двох реалізацій цієї практики**, а не універсальне визначення слів Worker та Agent. Агент може працювати й локально; функція може містити складну логіку або викликати модель. Для цього експерименту вирішальною відмінністю є явний міжпроцесний контракт.

## 8. Сценарії запуску й перевірки

### 8.1. Нормальний mock-запуск

Виконайте команди зі швидкого запуску. Доступні адреси:

```text
http://127.0.0.1:4100/health
http://127.0.0.1:4100/.well-known/agent-card.json
http://127.0.0.1:3000/health
POST http://127.0.0.1:3000/api/workflow/report
```

Нормальна mock-відповідь має два зведення, два джерела, один виклик Writer, один Reviewer, нуль токенів і `lab.backend: "mock"`. Позначки джерел у тексті перетворює на посилання оригінальний код workflow.

### 8.2. Kill the Agent

Залиште report-app запущеним і зупиніть research-agent через `Ctrl+C`. Повторіть POST. Report-app має залишитися живим і повернути безпечну помилку 502, а не запускати Writer із частковим дослідженням.

Запустіть research-agent знову. **Новий запит** може успішно пройти той самий маршрут. Старий невдалий запит не відновлюється автоматично. У mock-режимі цей сценарій відтворюється без ключа або витрат. Точна внутрішня помилка залежить від середовища: це може бути `ECONNREFUSED`, `fetch failed` або інше повідомлення транспортного шару.

### 8.3. Перехід на OpenRouter

У каталозі `a2a-lab/` створіть `.env` з `.env.example`. PowerShell:

```powershell
Copy-Item .env.example .env
```

Bash:

```bash
cp .env.example .env
```

Налаштуйте:

```dotenv
LAB_BACKEND=live
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_RESEARCH_MODEL=доступна_вам_модель_дослідника
OPENROUTER_WRITER_MODEL=доступна_вам_модель_автора
OPENROUTER_REVIEWER_MODEL=
```

Це місця для **власних секретів і конфігурації**, а не буквальні значення для API. Порожній `OPENROUTER_REVIEWER_MODEL` означає використання моделі Writer. За потреби доступний список `OPENROUTER_FALLBACK_MODELS` через кому. Конкретні назви моделей не зашиті в експеримент: доступність і підтримку потрібних параметрів перевіряють у своєму обліковому записі.

Перезапустіть **обидва процеси** з каталогу `a2a-lab/`. Research-сервіс потребує research-моделі; report-app потребує writer-моделі та, за наявності, reviewer-моделі. Налаштування із зовнішнього середовища процесу можуть мати пріоритет над `.env`.

Live-режим робить платні мережеві звернення. Пошук виконує дослідник, Writer і Reviewer не отримують інструмент вебпошуку. Сервер A2A не замінює Responses API: він лише переносить місце запуску існуючого Researcher.

Невдала автентифікація, несумісна модель, відсутні цитати або неповна відповідь провайдера не маскуються під успішний mock-результат. Змішування режимів двох процесів відхиляється.

### 8.4. Автоматичні перевірки

У комплекті 44 тести. Вони охоплюють контракт реальної практики, ProtoJSON round-trip, тип повідомлення, focus і backend, паралельні виклики, approved/limit_reached, невалідні входи, цитати, маскування помилок, timeout, клієнтське скасування, недоступність і повторний запуск локального агента. Оригінальний OpenRouterResearchWorker також тестується зі збереженими відповідями замість зовнішнього API.

`native-harness.mjs` — лише тестовий HTTP-хост на `node:http`. Він використовує справжній `JsonRpcTransportHandler` SDK; це не mock протоколу. Робочий сервер із додатка використовує офіційні Express-адаптери. Таким чином мережеві тести підтверджують A2A-шлях, але не повинні видаватися за окремий перевірений запуск кожної Express-точки входу.

Команда `npm test` спочатку синхронізує модулі, потім виконує повну TypeScript-збірку цільового npm-проєкту, а далі запускає тести. Межі перевірки під час підготовки комплекту точно зафіксовані у `a2a-lab/VERIFICATION.md`.

### 8.5. Подальший експеримент: окремий Reviewer

Можливий наступний крок — додати A2A-адаптер до контракту `ReviewerWorker`:

```text
ReportWorkflow
  ├── A2A → Research Agent
  ├── local → Writer
  └── A2A → Reviewer Agent
```

Цей другий сервіс **не реалізований у поточному комплекті** й не потрібний для його запуску. Writer можна залишити локальним, щоб не вводити ще одну сервісну межу без потреби в незалежному життєвому циклі або масштабуванні. Його live-виклик до OpenRouter при цьому нікуди не зникає.

Streaming, довговічне зберігання Task, remote cancellation, production-авторизація та розгортання на зовнішніх хостах не входять до цієї мінімальної lab.

## 9. Підсумок

**Workflow визначає маршрут. A2A стандартизує взаємодію між системами.** Ці рішення не є взаємовиключними: той самий детермінований супервізор може координувати локальні й віддалені ролі.

Корисність експерименту в тому, що справжній `ReportWorkflow` отримує той самий `ResearchBrief`, хоча дані пройшли через інший процес, ProtoJSON та HTTP. Помилки виявляються на конкретній межі, а не перетворюються на неповний звіт.

Фіксований маршрут не робить тексти LLM детермінованими. Валідація не доводить факти. Локальні тести не доводять доступність live-провайдера. Ці межі залишаються явними і в коді, і в результаті роботи.

```typescript
import { z } from "zod";
import type { ResearchBrief, ResearchFocus } from "./lesson08/report-workflow.js";

export const BackendSchema = z.enum(["mock", "live"]);
export type Backend = z.infer<typeof BackendSchema>;
export const FocusSchema = z.enum(["opportunities", "risks"]);
export const TopicSchema = z.string().trim().min(1).max(1000);
export const ResearchInputSchema = z
  .object({
    schemaVersion: z.literal(1),
    topic: TopicSchema,
    focus: FocusSchema,
  })
  .strict();
const SourceSchema = z
  .object({
    title: z.string().trim().min(1),
    url: z
      .string()
      .trim()
      .url()
      .refine((value) => {
        const protocol = new URL(value).protocol;
        return protocol === "http:" || protocol === "https:";
      }, "Потрібна HTTP(S) URL-адреса"),
  })
  .strict();
export const ResearchBriefSchema = z
  .object({
    focus: FocusSchema,
    summary: z.string().trim().min(1),
    sources: z.array(SourceSchema).min(1),
    tokenUsage: z
      .object({
        inputTokens: z.number().int().nonnegative(),
        outputTokens: z.number().int().nonnegative(),
        totalTokens: z.number().int().nonnegative(),
      })
      .strict(),
  })
  .strict();
// Це контракт нашого застосунку всередині A2A DataPart, не поле стандарту A2A.
export const ResearchPayloadSchema = z
  .object({
    schemaVersion: z.literal(1),
    backend: BackendSchema,
    brief: ResearchBriefSchema,
  })
  .strict();

export function parseResearchPayload(
  value: unknown,
  expectedFocus: ResearchFocus,
  expectedBackend: Backend,
): ResearchBrief {
  const payload = ResearchPayloadSchema.parse(value);
  if (payload.backend !== expectedBackend) {
    throw new Error("Режими report-app і research-agent не збігаються.");
  }
  if (payload.brief.focus !== expectedFocus) {
    throw new Error("Research Agent повернув інший focus.");
  }
  return payload.brief;
}
```

```typescript
export function positiveInteger(
  value: string | undefined,
  fallback: number,
  name: string,
  maximum = 600000,
): number {
  if (value === undefined || value.trim() === "") return fallback;
  const parsed = Number(value);
  if (!Number.isSafeInteger(parsed) || parsed < 1 || parsed > maximum) {
    throw new Error(`${name}: очікується ціле число від 1 до ${maximum}.`);
  }
  return parsed;
}
```

### A.13. `a2a-lab/src/a2a-research-worker.ts`

```typescript
import { randomUUID } from "node:crypto";
import { AgentCard, SendMessageRequest } from "@a2a-js/sdk";
import { ClientFactory, JsonRpcTransportFactory } from "@a2a-js/sdk/client";
import type { ResearchBrief, ResearchFocus, ResearchWorker } from "./lesson08/report-workflow.js";
import { ResearchInputSchema, type Backend } from "./contracts.js";
import { localAgentUrl } from "./environment.js";
import { parseResearchBrief } from "./a2a-brief-parser.js";

export class A2AResearchWorker implements ResearchWorker {
  public constructor(
    private readonly config: {
      agentUrl: string;
      backend: Backend;
      timeoutMs: number;
    },
  ) {
    localAgentUrl(config.agentUrl);
    if (!Number.isSafeInteger(config.timeoutMs) || config.timeoutMs < 1) {
      throw new Error("timeoutMs має бути додатним цілим числом.");
    }
  }

  public async research(
    topic: string,
    focus: ResearchFocus,
    signal?: AbortSignal,
  ): Promise<ResearchBrief> {
    const input = ResearchInputSchema.parse({ schemaVersion: 1, topic, focus });
    const base = localAgentUrl(this.config.agentUrl);
    const deadline = AbortSignal.timeout(this.config.timeoutMs);
    const combined = signal ? AbortSignal.any([signal, deadline]) : deadline;
    combined.throwIfAborted();

    // Один deadline охоплює і discovery, і SendMessage.
    // Заборона redirect та перевірка origin не дають AgentCard змінити довірений хост.
    const boundedFetch: typeof fetch = async (resource, init) => {
      const url = new URL(resource instanceof Request ? resource.url : resource.toString());
      if (url.origin !== base.origin || url.username || url.password) {
        throw new Error("AgentCard спрямовує виклик поза дозволений локальний origin.");
      }
      const inheritedSignal =
        init?.signal ?? (resource instanceof Request ? resource.signal : undefined);
      return fetch(resource, {
        ...init,
        redirect: "error",
        signal: inheritedSignal ? AbortSignal.any([combined, inheritedSignal]) : combined,
      });
    };
    const factory = new ClientFactory({
      transports: [new JsonRpcTransportFactory({ fetchImpl: boundedFetch })],
      cardResolver: {
        resolve: async (baseUrl, path) => {
          const response = await boundedFetch(
            new URL(path ?? "/.well-known/agent-card.json", baseUrl),
            {
              headers: { "A2A-Version": "1.0" },
            },
          );
          if (!response.ok) throw new Error("Не вдалося отримати AgentCard.");
          const card = AgentCard.fromJSON(await response.json());
          const expectedEndpoint = new URL("/a2a", base).href;
          if (
            !card.supportedInterfaces.some(
              (item) =>
                item.protocolVersion === "1.0" &&
                item.protocolBinding === "JSONRPC" &&
                item.url === expectedEndpoint,
            )
          ) {
            throw new Error("AgentCard не оголошує очікуваний A2A 1.0 JSONRPC endpoint.");
          }
          // Обирається лише попередньо перевірений інтерфейс, не довільні адреси картки.
          return {
            ...card,
            supportedInterfaces: card.supportedInterfaces.filter(
              (item) =>
                item.protocolVersion === "1.0" &&
                item.protocolBinding === "JSONRPC" &&
                item.url === expectedEndpoint,
            ),
          };
        },
      },
    });
    const client = await factory.createFromUrl(base.href);
    const request = SendMessageRequest.fromJSON({
      message: {
        messageId: randomUUID(),
        role: "ROLE_USER",
        parts: [{ data: input, mediaType: "application/json" }],
      },
    });
    const response = await client.sendMessage(request, { signal: combined });
    combined.throwIfAborted();
    return parseResearchBrief(response, input.focus, this.config.backend);
  }
}
```

### A.14. `a2a-lab/src/research-executor.ts`

```typescript
import { randomUUID } from "node:crypto";
import { Message, Role } from "@a2a-js/sdk";
import { RequestMalformedError, UnsupportedOperationError } from "@a2a-js/sdk/errors";
import {
  AgentEvent,
  type AgentExecutor,
  type ExecutionEventBus,
  type RequestContext,
} from "@a2a-js/sdk/server";
import type { ResearchWorker } from "./lesson08/report-workflow.js";
import { ResearchInputSchema, ResearchPayloadSchema, type Backend } from "./contracts.js";

export class ResearchAgentExecutor implements AgentExecutor {
  public constructor(
    private readonly researcher: ResearchWorker,
    private readonly backend: Backend,
    private readonly timeoutMs = 45000,
  ) {}

  public async execute(context: RequestContext, eventBus: ExecutionEventBus): Promise<void> {
    const message = context.userMessage;
    if (context.task) {
      throw new UnsupportedOperationError("Ця lab не підтримує продовження Task.");
    }
    const part = message.parts[0];
    if (
      message.role !== Role.ROLE_USER ||
      message.parts.length !== 1 ||
      part?.content?.$case !== "data" ||
      part.mediaType !== "application/json"
    ) {
      throw new RequestMalformedError("Потрібне user message з одним JSON data part.");
    }
    const input = ResearchInputSchema.safeParse(part.content.value);
    if (!input.success) {
      throw new RequestMalformedError("Некоректні schemaVersion, topic або focus.");
    }
    try {
      // Власний серверний timeout. Це не переданий по мережі клієнтський AbortSignal.
      const signal = AbortSignal.timeout(this.timeoutMs);
      const brief = await this.researcher.research(input.data.topic, input.data.focus, signal);
      signal.throwIfAborted();
      const payload = ResearchPayloadSchema.parse({
        schemaVersion: 1,
        backend: this.backend,
        brief,
      });
      if (payload.brief.focus !== input.data.focus) throw new Error("Невідповідний focus.");
      const response = Message.fromJSON({
        messageId: randomUUID(),
        contextId: context.contextId,
        role: "ROLE_AGENT",
        parts: [{ data: payload, mediaType: "application/json" }],
      });
      eventBus.publish(AgentEvent.message(response));
    } catch {
      // Ані prompt, ані URL провайдера, ані його error body не передаються клієнту.
      throw new Error("Research Agent не зміг сформувати валідне зведення.");
    }
  }

  public async cancelTask(_taskId: string, _eventBus: ExecutionEventBus): Promise<void> {
    throw new UnsupportedOperationError("Віддалене Task cancellation у цій lab не реалізоване.");
  }
}
```

```javascript
  InMemoryTaskStore,
  JsonRpcTransportHandler,
  ServerCallContext,
  UnauthenticatedUser,
} from "@a2a-js/sdk/server";

import { ResearchAgentExecutor } from "../dist/research-executor.js";

export async function startResearchHost(
  researcher,
  { backend = "mock", timeoutMs = 1000, cardTransform } = {},
) {
  let card;
  let transport;
  const requests = [];
  const server = createServer(async (req, res) => {
    try {
      if (req.url === "/.well-known/agent-card.json") {
        requests.push({ kind: "discovery", version: req.headers["a2a-version"] });
        res.setHeader("Content-Type", "application/json");

      }

        res.writeHead(404).end();
        return;
      }
      let body = "";
      for await (const chunk of req) body += chunk;
      const rpc = JSON.parse(body);
      requests.push({ kind: "rpc", version: req.headers["a2a-version"], rpc });
      const result = await transport.handle(
        rpc,
        new ServerCallContext({
          user: new UnauthenticatedUser(),
          requestedVersion: String(req.headers["a2a-version"] || ""),
        }),
      );
      if (result && Symbol.asyncIterator in result)
        throw new Error("Streaming is outside this test");
      res.setHeader("Content-Type", "application/json");
      res.setHeader("A2A-Version", "1.0");
      res.end(JSON.stringify(result));
    } catch {
      if (!res.destroyed) res.writeHead(500).end("test host error");
    }
  });
  const listen = (port) =>
    new Promise((resolve, reject) => {
      server.once("error", reject);
      server.listen(port, "127.0.0.1", () => {
        server.off("error", reject);
        resolve();
      });
    });
```
