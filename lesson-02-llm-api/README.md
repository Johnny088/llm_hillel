# Lesson 02 — Document API через OpenAI

> **Студентам курсу:** Почніть із [INSTRUCTION.md](../INSTRUCTION.md) – головної точки входу. Далі дотримуйтеся маршруту та правил [STUDENTS.md](../STUDENTS.md) для підготовки гілки, `my-dev/lesson-02-llm-api/` і здачі. Для цієї практики дивіться [student-guide.md](./student-guide.md) та [homework.md](./homework.md). Команди `*:my:lesson02:openai` перевіряють студентську папку; канонічні `*:lesson02` запускають starter або solution курсу.

У цій практиці текст надсилається до локального HTTP API. API робить два типи
запитів до OpenAI:

- повертає імена, дати, місця та короткий підсумок як перевірений JSON;
- повертає підсумок частинами через SSE-потік.

Графічного вебінтерфейсу немає. Найпростіша перевірка сама тимчасово запускає
сервер, показує всі запити й відповіді та зупиняє сервер після завершення.

## Найкоротший спосіб побачити результат

### 1. Відкрити PowerShell у корені практичного репозиторію

```powershell
# Команди виконуються з кореня репозиторію, де розташований package.json.
```

### 2. Один раз підготувати проєкт і `.env`

```powershell
yarn install --immutable
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

У `.env` потрібно заповнити:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI
OPENAI_MODEL_FAST=ідентифікатор_моделі_для_підсумку
OPENAI_MODEL_MAIN=ідентифікатор_моделі_для_вилучення_даних
```

Замість пояснювального тексту після `=` вставляються справжні значення без
лапок і кутових дужок. Ключ створюється на сторінці
[OpenAI API keys](https://platform.openai.com/api-keys), а ідентифікатори
обираються в [офіційному каталозі моделей](https://developers.openai.com/api/docs/models)
з урахуванням доступу конкретного API-акаунта. Для обох задач можна вказати
одну доступну модель. API key не додається до Git.

> Демонстрація виконує два реальні запити до OpenAI й може бути платною.
> Підписка ChatGPT та баланс OpenAI API — різні речі.

### 3. Запустити автоматичну демонстрацію

```powershell
yarn demo:lesson02:solution
```

Команда послідовно покаже:

1. `GET /health` → `HTTP 200, status=ok`;
2. `POST /api/documents/extract` → імена, дати, місця, підсумок, модель, час
   і токени;
3. `POST /api/documents/summary/stream` → повний зібраний текст, модель, час до
   першого фрагмента, загальний час і токени.

Останній успішний рядок має бути таким:

```text
=== ПІДСУМОК: УСІ 3 ПЕРЕВІРКИ ПРОЙДЕНО, ПРОЄКТ ПРАЦЮЄ ===
```

Після цього тимчасовий сервер уже зупинено — натискати `Ctrl+C` не потрібно.
Якщо виведено `ДЕМОНСТРАЦІЮ НЕ ПРОЙДЕНО`, текст у цьому рядку пояснює, на якому
етапі сталася помилка.

Власний текст передається в лапках:

```powershell
yarn demo:lesson02:solution "3 вересня Марія Савчук проведе воркшоп у Києві."
```

## Що запускати студенту

- `solution/` — готовий робочий варіант;
- `starter/` — навчальна заготовка з `TODO` і відповідями `501 NOT_IMPLEMENTED`;
- `checkpoints/01-streaming/` — проміжний стан після реалізації streaming.

Поточна папка не перемикає варіант автоматично. Команди можна виконати з
кореня репозиторію, з `lesson-02-llm-api`, `starter` або `solution`, але назва
команди завжди визначає ціль:

| Команда                       | Що запускається                           |
| ----------------------------- | ----------------------------------------- |
| `yarn demo:lesson02:solution` | готовий solution і повна автодемонстрація |
| `yarn dev:lesson02:solution`  | готовий solution як постійний сервер      |
| `yarn dev:lesson02`           | навчальний starter                        |

## Перевірка готового рішення без OpenAI

```powershell
yarn check:lesson02:solution
```

Команда не робить реальних API-запитів. Вона перевіряє структуру, форматування,
типи, unit та HTTP integration тести, checkpoint-тести, 5 offline eval cases і
production build.

## Ручний режим сервера

Він потрібен, якщо потрібно самостійно надіслати HTTP-запити. Тут необхідні два
вікна PowerShell. Покрокова інструкція й очікувані відповіді наведені в
[solution/README.md](solution/README.md).

## Якщо запуск не вдався

- `Некоректна конфігурація` — у кореневому `.env` порожній один із потрібних
  рядків.
- `HTTP 401` — OpenAI відхилив API key.
- `HTTP 429` — вичерпано ліміт або немає доступного API-балансу.
- `INCOMPLETE_RESPONSE` — модель не завершила відповідь у заданому ліміті
  токенів; можна збільшити `OPENAI_MAX_OUTPUT_TOKENS` у `.env` і повторити.
- `ERR_CONNECTION_REFUSED` — постійний сервер не запущено або він уже
  зупинився.
- Після `yarn dev:lesson02:solution` одразу повернувся PowerShell prompt — сервер
  завершив роботу; потрібно прочитати повідомлення про помилку вище.
