# Lesson 04 OpenRouter – студентський маршрут

Робоча папка для коду: `my-dev/lesson-04-mcp-built-in-tools-openrouter/`. Одноразово виконайте `yarn student:init 04 openrouter` з кореня репозиторію. Команда створить фізичну копію Lesson 04 starter і відмовиться перезаписувати наявну папку. Не переносіть архітектурні імпорти з інших уроків.

## Послідовність

1. Підготуйте власну гілку за основною інструкцією курсу й одноразово виконайте `yarn student:init 04 openrouter`. Якщо команда повідомляє, що destination вже існує, збережіть роботу й продовжуйте в ній без повторної ініціалізації.
2. Звірте точний baseline командою:
   ```powershell
   yarn verify:lesson04:openrouter:scaffolding
   ```
   Ця перевірка підтверджує канонічний baseline, а не копію my-dev і не реалізацію MCP. Точне порівняння my-dev за файлами та SHA-256 описано в [migration guide](./dev-migration-guide.md).
3. Прочитайте [домашнє завдання](./homework.md), [опис starter](./starter-code-guide.md), а потім пройдіть кожний обов'язковий крок [roadmap](./roadmap-code-guide.md). Не перескакуйте проміжні перевірки.
4. Запустіть фінальний gate з кореня репозиторію: yarn check:my:lesson04:openrouter. Переконайтеся, що в вашій папці немає файлів із секретами.
5. Перевірте в виводі completion gate окремий local MCP smoke результат. Він запускає локальний subprocess на синтетичній sandbox-копії, без provider inference.
6. Підготуйте здачу звичайним процесом курсу. Додайте короткий звіт про gate, smoke і те, чи виконувався live inference.

Якщо перший крок підготовки вже виконувався, звірте вміст до будь-якого оновлення. Не запускайте повторну ініціалізацію, яка може перезаписати my-dev.

## Що має вийти

В власній реалізації успадковані маршрути й локальні функції зберігаються. Research endpoint додає обмежений доступ до тексту в окремій sandbox через filesystem Model Context Protocol (MCP) server, а запит на актуальні зовнішні відомості може використати hosted web search OpenRouter. Sandbox задає межу локального читання; сервер запускається як subprocess через stdio, а його відповіді проходять через вузький allowlist.

Успіх стандартної здачі підтверджується offline gate і local Model Context Protocol (MCP) smoke. Recorded replay перевіряє підготовлені приклади. Жоден із цих результатів не доводить доступність чи якість live provider inference; цей крок залишається необов'язковим.
