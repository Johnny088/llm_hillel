# Lesson 04 OpenRouter – домашнє завдання

## Мета

Розширити локально успадковану основу Lesson 03 так, щоб research-agent міг прочитати файл у власній sandbox-папці через Model Context Protocol (MCP) і, за окремим запитом, скористатися hosted web search OpenRouter. Працюйте лише в my-dev/lesson-04-mcp-built-in-tools-openrouter/.

## Функціональні вимоги

- Збережіть усі успадковані маршрути та сервіси. Lesson 04 має власну локальну реалізацію, без імпорту готового Lesson 03 solution під час виконання.
- Запустіть filesystem Model Context Protocol (MCP) server локально через stdio transport. Передавайте моделі лише дозволені файлові інструменти, перевіряйте назву інструмента й аргументи перед кожним викликом та не дозволяйте доступ поза sandbox root.
- Не показуйте моделі чи HTTP-відповіді абсолютні локальні шляхи та внутрішні помилки subprocess. Перетворюйте помилки доступу на стабільні безпечні коди.
- Підтримайте OpenRouter server tool для web search, збереження provider continuation-повідомлень і точні метрики, сумісні з успадкованим API-контрактом.
- Обмежте один локальний запуск агента одним MCP tool round. Завершуйте HTTP-запит після відповіді агента або безпечної структурованої помилки.
- Закривайте MCP client, transport і породжений subprocess як при штатному завершенні, так і при помилці.
- Замініть лише навмисно визначені незавершені частини. Збережіть успадковані файли, шляхи, наявні сценарії eval і перевірки.
- Не виконуйте живі запити до OpenRouter як частину стандартної перевірки.

## Перевірка

Одноразово створіть студентську копію командою `yarn student:init 04 openrouter`. Після цього запустіть canonical baseline check:

```powershell
yarn verify:lesson04:openrouter:scaffolding
```

Під час роботи запускайте цільові перевірки з roadmap. Завершений student gate:

```powershell
yarn check:my:lesson04:openrouter
```

Очікується успішне завершення кожного етапу команди, нуль тестів зі статусом todo чи skipped та успішний recorded eval. Фактичну кількість успадкованих тестів визначає поточний повний набір, її не слід підміняти старими значеннями зі збережених нотаток. Student completion gate запускає local Model Context Protocol (MCP) smoke на синтетичній sandbox-копії. Його результат фіксується окремо від unit tests і recorded eval.

Якщо gate повідомляє про невідповідність baseline, не копіюйте solution поверх власних змін. Визначте конкретну різницю та виправте лише підтверджене відхилення. Student-команди спрямовані в `my-dev/lesson-04-mcp-built-in-tools-openrouter/`; `starter/` і `solution/` залишаються канонічними джерелами для читання.

## Межі доказів

Offline тести й recorded replay перевіряють логіку без живого провайдера. Local MCP smoke перевіряє stdio-зв'язок із локальним файловим сервером. Опційна демонстрація OpenRouter окремо перевіряє реальний provider inference і може витрачати баланс. Успіх одного рівня не є доказом для іншого; live-запит не потрібен для здачі.

## Здача

Пройдіть звичайний курсівський процес перевірки й підготовки гілки. У звіті вкажіть гілку, commit SHA, результат student gate, результат local Model Context Protocol (MCP) smoke та окремий статус live inference: не виконувався, пройшов або зупинений провайдером. Не додавайте секрети, журнали з ключами або локальні абсолютні шляхи.
