# Контрольна точка фінального проєкту – Lesson 04

Ці напрямки демонструють, як поєднати вузький доступ до локальних файлів через Model Context Protocol (MCP) із перевіркою актуальних зовнішніх джерел. Обирайте та реалізуйте власний варіант лише коли checkpoint призначив викладач.

## Варіант 1. Асистент аудиту репозиторію

- Проблема: під час аудиту потрібно зіставляти локальні текстові правила з актуальною документацією.
- Дані: невеликий набір дозволених Markdown або JSON файлів і офіційні сторінки проєкту.
- Результат: звіт із окремими посиланнями на локальні фрагменти та зовнішні джерела.
- Межі: не відкривати секрети чи файли поза sandbox; перевіряти, що вебджерело справді підтверджує висновок.

## Варіант 2. Помічник з оновлення залежностей

- Проблема: список застарілих залежностей треба зіставити з поточними релізами та повідомленнями безпеки.
- Дані: синтетичний package manifest у sandbox і офіційні release/security сторінки.
- Результат: перелік версій для перевірки з датою й URL джерела.
- Межі: не виконувати код пакетів; перед рекомендацією перевіряти сумісність із проєктом.

## Варіант 3. Пошук у локальних робочих інструкціях

- Проблема: відповіді часто потребують зіставити внутрішню коротку інструкцію з актуальними відкритими технічними відомостями.
- Дані: вигадані або спеціально підготовлені публічні робочі нотатки та офіційні сторінки.
- Результат: коротка відповідь із чітким розділенням локальних правил і зовнішніх фактів.
- Межі: не передавати приватні нотатки провайдеру без дозволу; не подавати згенерований текст як підтверджений факт.

Жоден варіант не вимагає доступу до справжніх приватних документів або live provider-виклику для offline перевірки.
