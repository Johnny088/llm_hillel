# Lesson 03 OpenRouter – маршрут викладача

## Мета, цінність і поведінка застосунку

### 🎯 Мета проєкту

Додати перевірене виконання `convert_currency` до успадкованого Document API через `POST /api/agent`.

### 💎 Практична цінність застосунку

Практика відділяє вибір дії моделлю від перевірки аргументів і виконання функції програмою.

### ⚙️ Що робить застосунок

`src/services/tool-calling-agent.ts` читає tool call, `src/tools/currency.ts` перетворює валідовані аргументи на локальний результат, а route повертає текст та usage.

## Послідовність live coding

1. Покажіть schema в `src/schemas/agent-request.ts`; попросіть назвати поля, які можуть прийти від користувача, до читання коду агента.
2. В `src/services/tool-calling-agent.ts` розберіть цикл: відповідь без tool call завершує хід; tool call перевіряється; лише потім запускається `convert_currency`; результат функції повертається моделі для фінальної відповіді.
3. Відкрийте `src/tools/currency.ts` і `tests/tool-calling.test.ts`. Тримайте курс синтетичним, щоб результат не залежав від мережі чи актуального валютного ринку.
4. Перевірте HTTP boundary через `tests/agent-route.test.ts`; некоректний payload не має дійти до агента.

## Контрольні точки з відповідями

- На запит «конвертуй 10 USD в UAH» очікуйте tool call з сумою та кодами валют; після schema validation локальна функція повертає число, яке використовується в фінальній відповіді. Курс – fixture, не live quote.
- Підмініть argument на від’ємну суму або невідому валюту. Очікувана відповідь: валідація відхиляє дані, функція не виконується, довільний код не запускається.
- Поверніть звичайний текст без tool call. Очікувана відповідь: один завершений model turn без вигаданого виклику інструмента.
- Запитайте, що означає usage: це лічильники відповіді провайдера, а не точність фінансового розрахунку.
