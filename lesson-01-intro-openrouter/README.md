# Lesson 01 (OpenRouter) — перший запит до мовної моделі

> **Студентам курсу:** Почніть із [INSTRUCTION.md](../INSTRUCTION.md) – головної точки входу. Далі виконуйте маршрут із [STUDENTS.md](../STUDENTS.md), де описано підготовку гілки, робочої папки та здачу. Для виконання уроку відкрийте [student-guide.md](./student-guide.md) та [homework.md](./homework.md).

Практика запускає одноразовий застосунок командного рядка та надсилає текстовий
запит до DeepSeek V4 Flash через OpenRouter. Запити можуть мати вартість.

**CLI (Command-Line Interface)** — програма, яка працює в терміналі.
**LLM (Large Language Model)** — велика мовна модель, що формує текстову
відповідь. **API (Application Programming Interface)** — програмний інтерфейс
для обміну даними із зовнішнім сервісом. Окремий сервер, браузер і графічний
інтерфейс у цій практиці не потрібні.

## Як одразу побачити результат

### 1. Відкрити PowerShell у корені репозиторію

```powershell
# Команди виконуються з кореня репозиторію, де розташований package.json.
```

Правильний каталог містить `package.json`, `.env.example` і папку
`lesson-01-intro-openrouter`.

### 2. Один раз підготувати проєкт

```powershell
yarn install --immutable
yarn env:init
notepad .env
```

В кореневому `./.env`, спільному для всіх практик, задається ключ OpenRouter:

```dotenv
OPENROUTER_API_KEY=sk-or-v1-...
```

Ключ створюється на сторінці <https://openrouter.ai/keys>. Реальний ключ не
додається до Git і не вставляється в README. `yarn env:init` створює кореневий
`.env` лише за його відсутності та не перезаписує наявні налаштування. Значення
з середовища процесу мають пріоритет над файлом. Для Lesson 01 модель за
замовчуванням – `~deepseek/deepseek-v4-flash-latest`, reasoning effort – `low`,
максимум відповіді – 1600 токенів, якщо кореневий `.env` і середовище процесу
не задають власного значення.

Якщо команда `yarn` не розпізнається, один раз виконується `corepack enable`,
після чого повторюється `yarn install --immutable`.

### 3. Запустити готовий `solution`

```powershell
yarn dev:lesson01:openrouter:solution "Обчисли 37 * 19. Поверни лише число."
```

## Що буде надіслано й отримано

У OpenRouter надсилається текст:

```text
Обчисли 37 * 19. Поверни лише число.
```

Успішний запуск має таку форму:

```text
📤 Надіслано:
Обчисли 37 * 19. Поверни лише число.
🎯 Основна модель: ~deepseek/deepseek-v4-flash-latest
⏳ Очікування відповіді OpenRouter...

📝 Відповідь:
703

🤖 Фактична модель: <ID, повернутий OpenRouter>
```

Критерій успіху: після напису `Відповідь` з'являється `703`, нижче вказується
фактична модель, а потім повертається запрошення PowerShell `PS ...>`.

Ідентифікатор (ID) фактичної моделі може відрізнятися від налаштованого, якщо
провайдер розкриває псевдонім (`alias`). Застосунок показує значення, повернуте
у відповіді.

## Який варіант використовувати

| Варіант    | Призначення                        | Команда запуску                               |
| ---------- | ---------------------------------- | --------------------------------------------- |
| `solution` | Готовий результат для демонстрації | `yarn dev:lesson01:openrouter:solution "..."` |
| `starter`  | Навчальне завдання з `TODO`        | `yarn dev:lesson01:openrouter "..."`          |

Суфікс `:solution` визначає готову версію. Поточна папка не перемикає `starter`
і `solution`. Для першого запуску рекомендується корінь репозиторію.

## Що реалізується у starter

- читання й безпечна перевірка змінних із `.env`;
- отримання тексту з аргументів CLI;
- один запит через OpenAI-сумісний API OpenRouter;
- один запит до явно налаштованої моделі;
- виведення відповіді та ID фактичної моделі;
- зрозумілі помилки без витоку ключа або provider body;
- unit-тести — автоматичні перевірки окремих функцій.

Порядок виконання наведено в [README навчального starter](./starter/README.md).

## Автоматична перевірка

Готове рішення повністю перевіряється командою:

```powershell
yarn check:lesson01:openrouter:solution
```

Команда перевіряє спільну політику налаштування однієї моделі в практиках 01–07,
а потім запускає lesson-local lint, форматування, typecheck, solution unit-тести та
build. Структурний course audit є окремою командою. Provider inference не
виконується, тому квота не витрачається.

## Якщо OpenRouter повернув HTTP 429

```text
❌ Не вдалося виконати запит: OpenRouter відхилив запит через обмеження частоти або доступності.
```

HTTP 429 може означати обмеження частоти, доступності або умов акаунта. Перевірте
статус і ліміти OpenRouter та повторіть запит пізніше. Запити до DeepSeek можуть
мати вартість.
