# Lesson 01 (OpenRouter) — solution

Готовий одноразовий застосунок командного рядка (CLI, Command-Line Interface)
надсилає один текстовий запит до великої мовної моделі (LLM, Large Language
Model) через OpenRouter, показує відповідь і завершує роботу. Окремий сервер або
браузер не запускається.

Повний вступ і вибір між `starter` та `solution` наведено в
[кореневому README практики](../README.md).

## Найпростіша перевірка

### 1. Перейти до кореня репозиторію

```powershell
# Команди виконуються з кореня репозиторію, де розташований package.json.
```

### 2. Один раз підготувати залежності та ключ

```powershell
yarn install --immutable
yarn env:init
notepad .env
```

Обов'язкове значення в спільному кореневому `./.env`:

```dotenv
OPENROUTER_API_KEY=sk-or-v1-...
```

Команда `yarn env:init` створює файл лише за його відсутності. Змінні
середовища процесу мають пріоритет над значеннями файла.

### 3. Запустити готове рішення

```powershell
yarn dev:lesson01:openrouter:solution "Обчисли 37 * 19. Поверни лише число."
```

Очікувана форма результату:

```text
📤 Надіслано:
Обчисли 37 * 19. Поверни лише число.
🎯 Основна модель: ~deepseek/deepseek-v4-flash-latest
⏳ Очікування відповіді OpenRouter...

📝 Відповідь:
703

🤖 Фактична модель: deepseek/...
```

Критерій успіху: відповідь дорівнює `703`, показано фактичну модель, після чого
процес завершується й повертається запрошення PowerShell.

## Що сталося під час запуску

1. Застосунок прочитав налаштування зі спільного кореневого `./.env` і
   врахував пріоритет зовнішніх змінних процесу.
2. Текст у лапках перетворився на user message.
3. OpenRouter отримав запит до налаштованої моделі. Запит може мати вартість.
4. У термінал виведено `message.content` та ідентифікатор (ID) моделі, яка
   реально відповіла.

## Запуск з іншої папки

Підготовка залежностей виконується з кореня репозиторію. Усі практики
використовують спільний кореневий `.env`. Команда з `:solution` працює також із
цих папок, бо Yarn знаходить батьківський `package.json`.

| Команда                                 | Фактично запускається         |
| --------------------------------------- | ----------------------------- |
| `yarn dev:lesson01:openrouter:solution` | Готовий `solution`            |
| `yarn dev:lesson01:openrouter`          | Навчальний `starter` з `TODO` |

Поточна папка не замінює суфікс `:solution`.

## Налаштування моделі

Основне джерело налаштувань — спільний кореневий `./.env`. Значення за
замовчуванням для Lesson 01 такі:

```dotenv
OPENROUTER_API_KEY=sk-or-v1-...
OPENROUTER_MODEL=~deepseek/deepseek-v4-flash-latest
OPENROUTER_REASONING_EFFORT=low
OPENROUTER_MAX_OUTPUT_TOKENS=1600
```

Змінні середовища процесу мають пріоритет над значеннями `.env`.

Окрім ключа, значення необов'язкові. За замовчуванням використовується модель
`~deepseek/deepseek-v4-flash-latest`, reasoning effort `low` і ліміт відповіді
`1600` токенів. Поле `Фактична модель` показує модель із відповіді
провайдера або налаштований ID, якщо провайдер його не повернув.

## Інший текстовий запит

```powershell
yarn dev:lesson01:openrouter:solution "Що таке closure у JavaScript?"
```

Текст відповіді та фактична модель можуть змінюватися між запусками.

## Автоматична перевірка без витрачання квоти

```powershell
yarn check:lesson01:openrouter:solution
```

Перевіряються структура курсу, lint, Prettier, TypeScript, unit-тести та build.
Unit-тести працюють без API-ключа й не надсилають запитів до мережі. Ручний
smoke test із попереднього розділу окремо підтверджує відповідь живої моделі та
потребує доступного ключа й мережі.

## Зрозумілі помилки

Якщо OpenRouter повернув HTTP 429, застосунок показує загальне повідомлення про
обмеження частоти або доступності:

```text
❌ Не вдалося виконати запит: OpenRouter відхилив запит через обмеження частоти або доступності.
```

Перевірте обмеження та стан акаунта OpenRouter, а потім повторіть запит пізніше.
Зайві повтори можуть мати вартість.

Інші безпечні повідомлення розрізняють відсутній ключ, неправильний input,
мережеву помилку, timeout і HTTP status. Provider body, заголовки та секрети не
виводяться.

## Безпека й обмеження

- Реальний ключ зберігається лише в спільному кореневому `./.env`, який
  ігнорується Git.
- У запит не передаються конфіденційні або персональні дані.
- `maxRetries: 0` не створює додаткових HTTP-запитів.
- Модель може відповідати повільно або тимчасово бути недоступною. Актуальні умови наведено в
  [OpenRouter FAQ](https://openrouter.ai/docs/faq).
